# Agent 工程实习 · 招聘 Skill

## 我们要什么样的人

要的是 **上手就能干活的 Agent 工程实习生**：进组第一周能跟现有代码、线上问题和评测动手，而不是只会背 LangGraph / RAG 名词。

不是「Agent 词很多但 nothing 落地」，不是「只会写 CRUD、Agent 一问三不知」，也不是「履历很宽、每个项目都浅」。

## 看人的三件事（必须同时有证据）

| 维度 | 要什么 | 不要什么 |
|------|--------|----------|
| **聪明度与潜力** | 苗子。能自己发现真问题、拆开、给出可验证的改法；面试能被追问到「为什么这样、坏了怎么办」仍不空 | 只会复述简历；换个角度就不会；数字经不起问（n 很小却 100%） |
| **广度与深度** | 有一定广度（后端/存储/Agent 不至于只懂一块），且 **至少 1 条线能追到 L3** | 技能表很长但每个项目只到 L1 pipeline；或只有深度没有协作/交付面 |
| **工程意识** | 项目里能看出对延迟、正确性、失败路径敏感。例如把「检索从 2–3 秒飙到 20 秒」当事故来修，而不是当正常耗时 | 只写「负责开发 XX 模块」；无超时/重试/幂等/观测/量级；对「十几秒」无感觉 |

**上手就做（硬门槛）：** 上面三维要落在 **真实实习 / 已上线系统** 上。能讲清公司或业务、自己写的模块、上线或内部用户、一个数字或 bad case。没有实习且无等价上线 → 默认降档。

**通过：** 三维都有证据 + 能独立讲完 FC 循环与终止、工具错误回传、失败怎么处理。  
**S / 强档：** 实习里做的就是那条能 L3 的线；工程意识有 **前后对比的量级**（耗时、压缩、P99、成功率）；能质疑自己的评测。  
**挂：** 无实习落地；或三维里缺两维；或纯名词堆砌。

## S 档校准（评估台当前样本）

用这些简历当「S 长什么样」，不要用技能表长度当 S。

| 校准点 | 合格信号（摘自 S 档） | 反例 |
|--------|------------------------|------|
| 工程意识 | 检索 20s→5s（-75%）；上下文 99 万字→12 万（-87%）；P99 2.57s→1.50s；20 并发压测写出 P99 | 「优化了性能」无前后数字；对十几秒无反应 |
| 上手就做 | 在已上线的 Agent 平台 / 接警 / 社交后端里 **独立负责** 一块并交付 | 只有课程大作业；「协助/参与」贯穿全段 |
| 深度 | 一条链路讲完：问题发现 → 方案 → 验证 → 上线（记忆分层、NL2SQL 校验纠错、幂等防超卖） | 五个项目每个三行 |
| 广度 | 后端（Redis/MQ/幂等）**加上** Agent/RAG，但深挖只盯一条 | 技能栏从 K8s 写到 LoRA，项目全是调用 API |
| 聪明度 | 能定位根因（会话 ID 未重置导致记忆串扰；重排误用原始分 0.24 而非融合分） | 只说「用了 LangGraph」 |

面试深挖优先问 **有数字、有事故、有 owner** 的那一条，不要让候选人按简历顺序报流水账。

## 怎么验「实习 / 上手就做」

**开场前看简历：** 有没有实习段？是否 ≥2 个月？技术栈是否接得上我们的后端 + Agent 仓库？

**必问四件套：**
1. **边界：** 团队做什么？你负责哪几块（具体到 module/接口）？
2. **产出：** 上线了吗？内部用户/请求量/指标是什么量级？
3. **协作：** 与 mentor 如何分工？Code review 你改过什么？
4. **深挖：** 这段实习里选 **一个你实现最深的点** 接到 STOP。

**合格：** 有自己写的模块名或接口；有 1 个数字或 bad case；进组后能想象他第一周改哪份代码。  
**红旗：** oral 对不上实习段；「协助开发」贯穿；「你独立完成了什么」沉默超过 10 秒。

**简历筛选：** 无实习且无「独立/上线/生产」→ `no_intern` 降档；有实习 + 工程意识数字 + 一条深挖 → 优先排期。

## 怎么验「聪明度与潜力」

不要单独考智商题。用深挖里的反应：

- 换一个约束（QPS×10、上下文超限、tool 超时不知道成没成功），他能不能重新设计，而不是重复简历原句。
- 数字是否自己算过：评测集多大、基线是什么、为啥信这个指标。
- 能否主动讲 **走弯路**：先做错什么、怎么发现的。

**合格：** 被追 3 刀仍有结构，能说取舍。  
**红旗：** 换说法就不会；把别人的架构当自己的；小样本 100% 还很得意。

---

## 怎么验「广度与深度」

**规则：整场只允许 1～2 个项目深挖，其中一个必须追到 L3。** 广度用「第二问点到即止」确认即可，不要巡游五个项目。

```
L1 是什么（架构）
L2 为什么（选型 / 职责拆分）
L3 坏了怎么办（可靠性 / merge / 降级）
```

**STOP：** Stop → Target（owner）→ One case（一个 rule/接口/module）→ Pain（翻车与修复）

**贡献分档：** 配置级（改参数） / 实现级（自己写模块） / 设计级（能设计 merge/评测/降级）。

---

## 怎么验「工程意识」

脑内翻译：Agent 词 → 接口 / 队列 / 超时 / 观测。

**必问：**
1. 输入输出契约？
2. 状态存哪？
3. 失败了怎么办？（超时、重复消费、tool 失败）
4. **慢了你怎么知道、怎么收？**（「十几秒」是否会当故障）

**合格：** 有 trade-off、幂等/重试、1 个真实 bad case，且对延迟/正确性有前后对比。  
**红旗：** 堆 Redis/LangGraph 名词；pipeline 介绍 5 分钟；觉得 20 秒检索「还能接受」。

## 面试结构（45 min 默认）

| 时段 | 验什么 |
|------|--------|
| 0～5 min | 对齐：我们要上手就做的人；确认实习；自选 1 个最深的点 |
| 5～20 min | 实习边界 + 单项目深挖到 L3（工程意识穿插：耗时/失败） |
| 20～32 min | 补短板：后端弱则问队列/幂等；Agent 弱则问 FC 循环 |
| 32～42 min | Agent 基础题 1 道 或 换约束的设计题（验潜力） |
| 42～45 min | 预期对齐 + 反问 |

开场：
> 岗位偏工程，要能马上跟线上问题动手。请先说最有代表性的一段实习，再选一个你改动最大、最好有数字的点；我会问根因、失败和你怎么验证。

## Agent 基础线（实习必过，挂 2 道可停）

1. **循环：** user → assistant(tool_calls) → role=tool 回填 → finish / max_turns。
2. **工具：** JSON Schema；校验失败当 tool result 回传；超时 ≠ 没发生（副作用要幂等键）。
3. **规划：** ReAct vs DAG；依赖能否预知。
4. **Context：** 发给模型的 ≠ Trace 全文。
5. **评测：** 问 baseline、任务集、轨迹；小 n 100% 要质疑。

现场口述：两个并行 tool_call 怎么回填；A→C,B→C 且 A 失败；HTTP 超时且不知是否执行。

## 评分与结论

| 档位 | 条件 |
|------|------|
| **S / 推荐** | 上手就做 + 聪明度 + 广度深度 + 工程意识均有证据；有量级闭环 |
| **A / 待定** | 苗子明显但实习偏短/无上线；或三维里一维弱 |
| **淘汰 / 不推荐** | 无实习落地；或纯名词；或对延迟/失败无意识且讲不清 owner |

面试官笔记：

```
上手就做（实习/上线/owner）：
聪明度（换约束后的反应）：
广度 vs 深挖到 L3 的那一条：
工程意识（耗时/失败/数字）：
结论：S推荐 / A待定 / 不推荐
```

反馈给候选人：感谢 → 最强点（具体）→ 2～3 条可改进 → 鼓励。避免内部评语腔。

## Agent 执行清单

1. 先对齐本文用人标准（上手就做 + 三维）。
2. 按简历选 **1 段实习 + 1 个有数字的深挖点**；补问短板维。
3. 产出追问清单 / 评分笔记 / 候选人反馈（按用户要的）。
4. 改 skill、评分 prompt 或飞书时，保持三维表述一致。
