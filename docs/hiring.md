# 用人标准

面向 **Agent 工程实习**：要 **上手就能干活** 的人，不是背名词的人。

详细面试话术、STOP 深挖、题库见招聘 Skill（`~/.claude/skills/agent-intern-recruiting`）和[飞书面试指南](https://weiguangdianliang.feishu.cn/docx/SaWcdQra4ovJDuxUXgWcGwt3nme)。评估台上传简历时的 LLM 评分与本文对齐（`backend/internal/scanner/scoring_prompt.txt`）。

## 我们要什么样的人

进组第一周能跟现有代码、线上问题和评测动手。

| 维度 | 要什么 | 不要什么 |
|------|--------|----------|
| **聪明度与潜力** | 苗子。能自己发现真问题、拆开、给出可验证的改法 | 只会复述简历；数字经不起问 |
| **广度与深度** | 有一定广度，且至少 1 条线能追到 L3（是什么 → 为什么 → 坏了怎么办） | 技能表很长但每个项目只到 pipeline 介绍 |
| **工程意识** | 对延迟、正确性、失败路径敏感。例如把「检索从 2–3 秒飙到 20 秒」当事故来修 | 对「十几秒」无感觉；无超时/重试/幂等/量级 |

**上手就做（硬门槛）：** 三维要落在真实实习 / 已上线系统上。能讲清 owner、上线或内部用户、一个数字或 bad case。

## S 档长什么样（校准）

不要用技能表长度当 S。更像 S 的信号：

- **工程意识有前后对比：** 检索 20s→5s；上下文压缩 87%；P99 从 2.57s 降到 1.50s；压测写出并发与 P99
- **上手：** 在已上线的 Agent 平台 / 业务后端里独立负责一块并交付
- **深度：** 一条链路写完问题发现 → 方案 → 验证 → 上线（而不是五个项目各三行）
- **潜力：** 能定位根因（例如会话 ID 未重置导致记忆串扰），而不是只写「用了 LangGraph」

## 档位

| 档位 | 条件 |
|------|------|
| **S** | 上手就做 + 三维都有证据；最好有耗时/失败/量级闭环 |
| **A** | 苗子明显但实习偏短/无上线，或三维里一维弱 |
| **淘汰** | 无实习落地；或纯名词；或对延迟/失败无意识且讲不清 owner |

自动评分：上传/拖入简历走 ModelHub（prompt 见 `scoring_prompt.txt`）。全库 `POST /api/rescreen` 仅启发式，不调用模型。图片 PDF 可能不准，以人工档位和原件为准。
