# 影像 && 软件 测试

要 **上手就能验** 的人：进组第一周能对着真实页面、影像结果和坏例动手，不是背测试理论或只会点一遍主路径。

## 岗位职责

- 影像侧：验生成图 / 试衣 / 构图质量，把「看起来不对」写成可复现的坏例（输入、预期、实际、是否必现）
- 软件侧：跟功能、回归和线上问题，覆盖主路径之外的失败、超时、空态和权限边界
- 能独立把一块验证做到可交接：步骤、数据、截图或日志，下一个人能按同样步骤复现

## 我们要什么样的人

| 维度 | 要什么 | 不要什么 |
|------|--------|----------|
| **观察力** | 能看出影像伪影、穿模、色偏、裁切、文案错位等具体问题 | 只说「感觉不好」或「有 bug」，给不出复现 |
| **验证方法** | 会拆主路径 / 边界 / 失败路径；知道什么该截图、什么该对日志 | 只会点一遍快乐路径；用例写完从不跑 |
| **工程意识** | 对必现/偶现、环境差异、脏数据敏感；会追「为什么这次才坏」 | 把偶现当没发生；环境配不好就停 |

**硬门槛：** 有真实测试实习或等价落地（提过缺陷、写过可执行用例、跟过上线/回归）。仅课程作业、无缺陷描述，默认不够。

## 加分

- 做过图像 / 视频 / 生成内容相关测试，能讲清「怎么判一张图不合格」
- 能把偶现打成必现：环境、数据、时序或并发条件
- 会用脚本或简单工具减轻重复点选，而不是纯手工流水账

## 档位（评估台）

| 档位 | 条件 |
|------|------|
| **S** | 上手就验 + 能独立写清坏例与回归范围；最好有影像质量或线上问题闭环 |
| **A** | 苗子明显但实习偏短，或观察力 / 验证方法里一维弱 |
| **淘汰** | 无测试落地；或只会背用例模板；或讲不清自己提过什么缺陷 |

上传简历时按本岗绑定的检验标准自动评分；面试以简历原件、坏例描述和人工档位为准。
