# 影像 && 软件 测试

面向 **约三年经验、偏执行** 的 QA：进组就能上手验画质、跑安卓，不是背测试理论、也不是只会点一遍主路径。要有比较强的主观能动性——自己发现问题、把问题定位到大致模块，而不是等别人派任务。

## 岗位职责

- **影像侧（IQ）**：做画质评定。主观验证覆盖 AWB、AE、清晰度、影调；同时能做客观实验室指标评定（含图像类指标），把「看起来不对」写成可复现的坏例（输入、预期、实际、是否必现）
- **软件侧（安卓）**：完整安卓测试，从测试用例写到大项目的测试计划与排期都能独立做完；跟功能、回归和线上问题，覆盖主路径之外的失败、超时、空态和权限边界
- **定位**：发现问题后能大致判断落在哪个模块（应用 / Camera / 算法 / 框架等），把验证做到可交接（步骤、数据、截图或日志）

## 我们要什么样的人

| 维度 | 要什么 | 不要什么 |
|------|--------|----------|
| **IQ 画质** | 做过主观验证（AWB / AE / 清晰度 / 影调），也做过实验室客观指标；能讲清「这张图为什么不合格」 | 只会说「画质不好」或「有色偏」，给不出评定方法和复现 |
| **安卓测试** | 从用例到项目测试计划/排期都做过；执行力强，能把一块测试完整跑完 | 只会点快乐路径；用例写完从不跑；没做过排期、没扛过项目节奏 |
| **主观能动** | 自己找问题、定位到模块；偶现会追环境/数据/时序 | 等分配；把偶现当没发生；环境配不好就停 |

**硬门槛：** 约三年左右真实测试经验（正式 QA / 等价落地），提过缺陷、写过可执行用例，并且跟过安卓项目测试。仅课程作业、纯实习打杂、无缺陷/无排期描述，默认不够。

## 加分

- 能把 IQ 主观结论和实验室客观指标对上（同一坏例两边都能说）
- 能把偶现打成必现：环境、数据、时序或并发条件
- 会用脚本或简单工具减轻重复点选，而不是纯手工流水账

## 档位（评估台）

| 档位 | 条件 |
|------|------|
| **S** | 约三年执行力够用；IQ（主观 AWB/AE/清晰度/影调 + 实验室客观指标）和安卓全流程（用例→项目计划/排期）都有证据；能自己发现问题并定位到模块 |
| **A** | 约三年偏执行、能动性强，但 IQ 与安卓里一侧明显偏薄；或年限够但独立排期/定位模块写得弱 |
| **淘汰** | 无真实 QA 落地；或只会背模板；或讲不清自己怎么评画质、怎么排过安卓测试；纯实习打杂不够 |

上传简历时按本岗绑定的检验标准自动评分；面试以简历原件、画质评定方法和人工档位为准。
